# Maestro iOS runner patches

`scripts/build-maestro-runner.sh` builds Maestro's iOS XCTest runner from the `cli-2.10.0` source, pinned by its sha256, and applies these patches in order. The CI iOS lanes run that build instead of the runner bundled with the Maestro CLI.

- `0001-keep-serving-after-xctest-issues.patch`: the runner serves its HTTP API from inside one XCTest method, so any issue XCTest records, such as a screenshot or accessibility timeout on a slow simulator, ends that test and takes the server down ([mobile-dev-inc/maestro#3538](https://github.com/mobile-dev-inc/maestro/issues/3538)). The patch logs the issue instead and returns it as the error of the request that caused it.
- `0002-lead-in-touch-paths.patch`: each synthesized tap or swipe gets its own virtual digitizer, and a touch that reaches backboardd before that digitizer is attached is dropped ([mobile-dev-inc/maestro#3686](https://github.com/mobile-dev-inc/maestro/issues/3686)). The patch starts every touch path 50 ms in. It does not prevent the case where backboardd receives the digitizer's first event before caching its sender ("unknown senderID"), keeps two touch records, and cancels the touch with its contact still down; `scripts/simulator-touch.mjs` recognizes that case.

Delete a patch when a Maestro release ships its fix, and delete this directory and the build script when Maestro 3.0 replaces `maestro-ios-xctest-runner`. The pinned source hash, plus patches that must apply to it, is how these are tracked: moving to a new Maestro version means updating the tag and hash, and the build fails on any patch that no longer applies.
